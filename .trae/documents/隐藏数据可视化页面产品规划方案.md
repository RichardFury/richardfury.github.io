# Richard Fury 个人网站隐藏数据可视化页面产品规划方案

## 一、产品定位与战略目标

### 1.1 产品定位
为Richard Fury个人网站设计一个隐藏的数据可视化后台页面，作为数据科学家的个人数据实验室，用于展示和分析网站访问数据，体现数据科学家的专业能力和技术洞察力。

### 1.2 战略目标
- **技术展示**：通过数据可视化展示数据科学家的技术能力
- **个人品牌**：增强个人网站的专业性和深度
- **数据洞察**：为网站运营提供数据支持
- **隐私保护**：通过密码保护确保数据安全
- **用户体验**：提供流畅、美观的数据探索体验

### 1.3 成功指标
- 页面加载时间 < 2秒
- 数据更新延迟 < 5分钟
- 可视化交互响应时间 < 300ms
- 密码保护安全性达到企业级标准
- 数据准确性达到99.9%

## 二、目标用户分析

### 2.1 主要用户
**Richard Fury（网站所有者）**
- **角色**：数据科学家、网站管理员
- **需求**：
  - 实时监控网站访问情况
  - 分析用户行为模式
  - 了解访问者地理分布
  - 评估内容受欢迎程度
  - 优化网站性能和用户体验
- **技术能力**：高（数据科学家，熟悉数据分析）
- **使用频率**：每日/每周

### 2.2 次要用户
**潜在雇主/合作方**
- **角色**：招聘人员、项目合作方
- **需求**：
  - 了解数据科学家的技术能力
  - 评估项目经验和专业水平
  - 查看数据分析和可视化能力
- **技术能力**：中等
- **使用频率**：一次性/偶尔

### 2.3 用户旅程
```
发现隐藏页面 → 输入密码 → 进入仪表板 → 浏览数据 → 深入分析 → 导出报告 → 退出
```

### 2.4 用户痛点
- 现有分析工具（如Google Analytics）功能过于复杂
- 需要更直观、更个性化的数据展示
- 希望看到更详细的地理分布和用户行为数据
- 需要快速了解网站整体运营状况

## 三、核心功能需求

### 3.1 访问控制模块（优先级：高）

#### 3.1.1 密码保护功能
**功能描述**：通过密码保护隐藏页面，确保只有授权用户可以访问

**用户故事**：
- 作为网站所有者，我希望通过密码保护数据页面，以确保数据安全
- 作为授权用户，我希望通过输入密码快速访问数据页面

**验收标准**：
- 支持强密码（至少12位，包含大小写字母、数字、特殊字符）
- 密码错误时显示友好提示
- 密码正确后自动跳转到数据页面
- 支持会话保持（可配置过期时间）
- 防止暴力破解（失败次数限制）
- 密码哈希存储（不存储明文密码）

**技术实现**：
- 前端：Vue 3组件实现登录界面
- 后端：JWT token认证
- 存储：localStorage存储token
- 安全：bcrypt密码哈希

#### 3.1.2 隐藏入口机制
**功能描述**：设计隐蔽的页面入口，不公开显示在导航中

**用户故事**：
- 作为网站所有者，我希望数据页面入口隐蔽，避免普通用户发现

**验收标准**：
- 不在主导航中显示
- 通过特定URL路径访问（如/analytics）
- 可选：通过键盘快捷键触发
- 可选：通过页面特定元素触发（如点击页脚特定位置）

**技术实现**：
- 路由配置：`/analytics`路径
- 可选：全局键盘事件监听
- 可选：隐藏的DOM元素点击事件

#### 4.3.2 数据存储方案

**方案一：JSON文件存储（推荐初期使用）**
- 优点：简单、无需后端、易于部署
- 缺点：数据量大时性能下降、并发写入问题
- 适用场景：小规模数据、个人网站

**方案二：IndexedDB存储**
- 优点：浏览器本地存储、容量大、异步操作
- 缺点：API复杂、兼容性问题
- 适用场景：中等规模数据、需要离线支持

**方案三：外部API服务**
- 优点：专业服务、功能完善、易于集成
- 缺点：需要付费、数据隐私问题
- 选项：
  - Google Analytics
  - Plausible
  - Umami
  - 自建后端API

**方案四：云数据库（推荐长期使用）**
- 优点：可扩展、专业支持、实时同步
- 缺点：需要后端、成本较高
- 选项：
  - Firebase
  - Supabase
  - MongoDB Atlas
  - PostgreSQL

### 4.4 数据收集方案

#### 4.4.1 前端数据收集

**页面访问追踪**
```javascript
// 在每个页面加载时发送访问数据
function trackPageView() {
  const data = {
    timestamp: new Date().toISOString(),
    page: window.location.pathname,
    referrer: document.referrer,
    userAgent: navigator.userAgent,
    language: navigator.language,
    screen: {
      width: window.screen.width,
      height: window.screen.height
    }
  };
  sendToAnalytics(data);
}
```

**用户行为追踪**
```javascript
// 追踪点击事件
document.addEventListener('click', (e) => {
  const data = {
    type: 'click',
    target: e.target.tagName,
```

### 4.5 安全架构

#### 4.5.1 认证流程

```
用户输入密码
    ↓
前端验证密码格式
    ↓
发送到后端API（或前端验证）
    ↓
后端验证密码（bcrypt）
    ↓
生成JWT Token
    ↓
返回Token给前端
    ↓
前端存储Token（localStorage）
    ↓
后续请求携带Token
    ↓
后端验证Token
    ↓
允许访问数据
```

#### 4.5.2 前端验证（简化方案）

```javascript
// 前端密码验证（仅用于演示，生产环境需要后端）
const PASSWORD_HASH = '$2b$10$...'; // bcrypt哈希

async function verifyPassword(password) {
  const hash = await bcrypt.hash(password, 10);
  return hash === PASSWORD_HASH;
}

// 生成Token
function generateToken() {
  const payload = {
    exp: Math.floor(Date.now() / 1000) + (24 * 60 * 60), // 24小时过期
    iat: Math.floor(Date.now() / 1000)
  };
  return btoa(JSON.stringify(payload));
}

// 验证Token
function verifyToken(token) {
  try {
    const payload = JSON.parse(atob(token));
    return payload.exp > Math.floor(Date.now() / 1000);
  } catch {
    return false;
  }
}
```

```javascript
  } else if (to.path === '/analytics/login') {
```
